# 우리 반 공용 캘린더 — 서버 붙이기 실습

입장코드 하나로 들어가 **여럿이 같이 적는 달력**입니다.
앱은 다 만들어져 있습니다. 여러분이 할 일은 **서버를 붙이고 열쇠를 꽂는 것** 둘뿐입니다.

설치할 것이 없습니다. 브라우저만 씁니다. 다 하면 20분쯤 걸립니다.

---

## 완성하면 이렇게 됩니다

- 입장코드와 이름을 넣으면 달력이 열립니다
- 날짜를 누르면 한 줄을 적습니다 (40자까지)
- **다른 기기에서 열어도 같은 것이 보입니다** ← 서버가 붙었다는 증거
- 내가 적은 것은 30분 안에만 지웁니다
- (열쇠를 꽂으면) 생각나는 대로 적은 메모를 AI가 날짜로 갈라 줍니다

---

## 두 갈래가 있습니다. 먼저 어느 쪽인지 정하세요

### 빠른 길 — 강사가 준 서버를 같이 쓰기 (10분)

강사가 만들어 둔 서버에 다 같이 붙습니다. **미션 1 → 미션 5** 만 하면 됩니다.
미션 2·3·4(서버 만들기)는 건너뜁니다. 받은 환경변수 파일에 값이 이미 채워져 있습니다.

- 같은 달력을 반 전체가 같이 씁니다. **내가 적은 것이 옆자리 화면에도 뜹니다.**
  주소는 사람마다 다른데 서버가 하나라서 그렇습니다. 앱은 화면일 뿐이고 자료는 서버에 있습니다.
- 서로의 글이 다 보입니다. 개인정보는 적지 않습니다.
- 나만 쓰는 달력을 원하면 `ROOM_CODE` 만 다른 값으로 바꾸고 다시 배포하면 됩니다.
  서버는 그대로 쓰면서 달력만 갈라집니다.
- **연수가 끝나면 강사가 그 서버를 지웁니다. 그때 앱이 멈춥니다.**
  계속 쓰고 싶으면 아래 긴 길을 한 번 더 하면 됩니다. 앱은 그대로 두고 값만 바꿉니다.

### 내 것 만들기 — 내 서버를 새로 파기 (25분)

**미션 1부터 5까지** 전부 합니다. 내 계정에 만든 서버라 연수가 끝나도 그대로 남습니다.
교실에서 실제로 쓸 생각이면 이쪽입니다.

> 빠른 길로 먼저 성공을 본 뒤에 내 것을 만들어도 됩니다.
> 바꿀 것은 환경변수 두 줄뿐이고, 앱은 하나도 안 건드립니다.

---

## 미션 1. 내 저장소로 가져오기

1. 이 저장소 오른쪽 위 **Fork** 를 누릅니다.
2. 내 계정 아래에 같은 저장소가 생깁니다. 이제부터 이걸 씁니다.

---

## 미션 2. 서버(Supabase) 만들기  — 빠른 길이면 건너뜁니다

1. [supabase.com](https://supabase.com) → `Start your project` → 깃허브나 구글로 로그인
2. `New project`
   - Name: `calendar`
   - Database Password: 아무거나 적고 **따로 메모** (다시 안 보여 줍니다)
   - Region: `Northeast Asia (Seoul)`
3. `Create new project` 를 누르고 2분쯤 기다립니다.

**이러면 성공** — 프로젝트 이름 옆에 초록 점이 뜹니다.

> 무료 프로젝트는 **이레 동안 아무도 안 쓰면 잠깁니다.** 개학 전에 한 번 열어 두세요.

---

## 미션 3. 표 만들기  — 빠른 길이면 건너뜁니다

1. 왼쪽 메뉴 **SQL Editor** → `New query`
2. 이 저장소의 [`supabase/schema.sql`](supabase/schema.sql) **전체를 복사해서 붙여넣습니다.**
3. 오른쪽 아래 `Run`

**이러면 성공** — 아래에 `Success. No rows returned` 이 뜨고,
`Table Editor` 에 `events` 표가 보이며 이름 옆에 `RLS enabled` 가 붙습니다.

> 손으로 표를 만들지 마세요. 열 이름 한 글자만 달라도 앱이 안 붙습니다.
> **맨 아래 RLS 세 줄을 빼먹으면 링크를 아는 누구나 표를 통째로 지울 수 있습니다.**

---

## 미션 4. 값 두 개 복사하기  — 빠른 길이면 건너뜁니다

왼쪽 메뉴 **Settings** → **API** 에서 두 개를 메모장에 복사합니다.

| 이름 | 어디 있나 | 생김새 |
|---|---|---|
| Project URL | 맨 위 | `https://xxxxxxxx.supabase.co` |
| anon public | Project API keys | `eyJhbGciOi...` (아주 깁니다) |

> `service_role` 키는 **쓰지 않습니다.** 그 옆에 있지만 건드리지 마세요.

---

## 미션 5. Vercel 에 올리고 환경변수 꽂기

1. [vercel.com](https://vercel.com) → `Continue with GitHub` 로 로그인
2. `Add New...` → `Project` → 포크한 저장소 옆 `Import`
3. **Framework Preset 은 `Other` 로 둡니다.** 빌드 설정은 건드리지 않습니다.
4. `Environment Variables` 를 펼치고, **받은 환경변수 파일의 내용을 그대로 붙여넣습니다.**
5. `Deploy` 를 누르고 1분쯤 기다립니다.

**이러면 성공** — 나온 주소를 열면 입장 화면이 뜹니다.
입장코드와 이름을 넣고, 날짜를 눌러 한 줄 적어 보세요.
Supabase 의 `Table Editor` → `events` 에도 같은 줄이 보이면 서버가 붙은 것입니다.

---

## 안 될 때 — 여기 셋 중 하나입니다

| 화면 | 원인 | 해결 |
|---|---|---|
| **"아직 서버가 안 붙었습니다"** | 환경변수가 없거나 이름이 틀림 | 이름을 그대로 다시 넣고 **Redeploy** |
| 환경변수를 넣었는데 그대로임 | **다시 배포를 안 함** | `Deployments` → 맨 위 줄 `…` → `Redeploy` |
| 적으면 빨간 글씨가 뜸 | 표가 없거나 RLS 규칙이 없음 | 미션 3 의 SQL 을 다시 실행 |
| 적었는데 목록이 비어 있음 | RLS 의 `select` 규칙이 없음 | 같은 SQL 을 다시 실행 |

> **환경변수는 넣기만 하면 반영되지 않습니다.** 다시 배포해야 합니다.
> 실습에서 제일 많이 막히는 자리입니다.

## 안에 뭐가 들었나

```
index.html            앱 전체. 화면과 동작이 다 여기 있습니다
api/config.js         환경변수를 화면으로 내려 주는 서버 자리
api/assist.js         메모를 날짜로 갈라 주는 서버 자리 (AI 열쇠는 여기서만 씁니다)
supabase/schema.sql   표 만들기 + 자물쇠(RLS)
```

빌드 도구가 없습니다. `npm install` 도 없습니다.
`api/` 안의 파일만 서버에서 돌고, 나머지는 브라우저에서 돕니다.

### 환경변수 네 개

| 이름 | 무엇 | 없으면 |
|---|---|---|
| `SUPABASE_URL` | 내 서버 주소 | 앱이 안 열립니다 |
| `SUPABASE_ANON_KEY` | 공개용 열쇠 | 앱이 안 열립니다 |
| `ROOM_CODE` | 입장코드이자 **어느 달력이냐** | `1111` 로 열립니다 |
| `GROQ_API_KEY` | AI 열쇠 | AI 칸이 아예 안 보입니다 (나머지는 정상) |

---

## 왜 이렇게 만들었나

**anon 키는 숨기는 값이 아닙니다.** 브라우저로 나갈 수밖에 없습니다.
그래서 키로 지키지 않고 `schema.sql` 의 **RLS 규칙**으로 지킵니다 —
40자 넘는 글은 못 쓰고, 30분 지난 글은 아무도 못 지웁니다.

**GROQ 열쇠는 숨기는 값입니다.** 그래서 `api/assist.js` 안에서만 쓰이고
브라우저로 한 글자도 안 나갑니다.
배포한 뒤 페이지에서 `Ctrl+U` 를 눌러 소스를 열고 `gsk_` 를 검색해 보세요.
**아무것도 안 나오면 제대로 한 것입니다.**

## 조심할 것

- 공개 저장소입니다. **열쇠를 코드 안에 적지 마세요.** 환경변수에만 넣습니다.
- 학생 이름과 얼굴 사진, 전화번호는 넣지 않습니다. 화면에도 그렇게 안내가 떠 있습니다.
- 입장코드는 문지기일 뿐 자물쇠가 아닙니다. 링크를 아는 사람은 코드를 넣어 볼 수 있습니다.
